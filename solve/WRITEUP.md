# Flygammon (ctfcup 2026) — разбор

**Задача.** Обыграть «ИИ» в нарды 15 раз подряд; игра идёт на блокчейне, броски
костей выдаёт VRF-оракул, затем `GET /flag`, если `isSolved()` истинно.

**Результат.** Флаг добыт (приведён в чате; в репозитории намеренно не публикуется).
Уязвимость — полностью гладкое `p-1` в VRF: дискретный логарифм секрета оракула
считается за доли секунды, после чего становятся известны **все** броски любой
будущей партии.

## 1. Что на инстансе

`GET /` отдаёт:

```
RPC endpoint : https://<instance>
player key   : 0xeb42...20fb      # приватный ключ игрока (!)
challenge    : 0x9fE46736679d2D9a65F0992F2272dE9f3c7fa6e0
goal         : win 15 games in a row, then GET /flag
```

Цепь — `anvil` (`eth_chainId = 31337`). Контракты из handout:

* `Flygammon.sol` — `commit()` (стоит 1 токен), `skip()` (бесплатно, `gameId+1`),
  `playerMove`, `oracleTurn`, `postDice`, `isSolved()`;
* `Engine.sol` — правила нард, упаковка доски в `uint256`;
* `VRF.sol` — Chaum–Pedersen DLEQ над `Z_p^*`; `p`, `g`, `h` — `immutable`,
  читаются из контракта (`P`, `G`, `H`).

Флоу хода: игрок `commit()` → демон-оракул постит доказанные кости
`postDice(y,a1,a2,z)` → игрок `playerMove(froms,dies)` → оракул постит свои кости и
ход `oracleTurn(...)`.

## 2. Уязвимость: гладкое p−1

```
P = 59542135019038253973229890950380403852748593264440878510381149952935803452287
G = 5
H = 33000356474693902489206072769680218785232483244014366506670537756187581196069
P-1 = 2 · 558937 · 617857 · 1042901 · 751823 · 870169 · 877321 · 501637
        · 798131 · 897263 · 989743 · 762389 · 783829 · 677827
```

Все простые множители `p-1` ≤ ~1.04·10^6, `g` — первообразный корень. Значит
`log_g(h)` берётся Pohlig–Hellman + BSGS:

```
s = 44429351088910330309877229617525065651981599688549971109269094157417387525861
```

(см. `solve/dlp.py`; проверка `g^s == h` и совпадение предсказанных `y`/костей со
всеми `DicePosted` в цепи).

## 3. Что даёт знание s

* `y = u^s mod p`, где `u = keccak("flygammon-vrf-u" ‖ gameId ‖ turn) % p`, а кости —
  `keccak("flygammon-vrf-dice" ‖ y)`. Значит **любой** бросок для любой пары
  `(gameId, turn)` известен заранее.
* `skip()` бесплатен и увеличивает `gameId` на 1 → можно перебирать «сиды» партий
  и выбирать ту, где кости благоволят игроку (например, серии 6-6/5-5 игроку и
  мелкие дубли оракулу).
* `model.fly` + `engine.rs` + `agent.rs` есть в handout: оракул играет
  детерминированно (`choose_2ply`, без exploration), поэтому партию можно
  отсимулировать оффлайн (порт движка/модели или сборка `model-src` на раннере) и
  коммититься только в те `gameId`, где выигрыш гарантирован.

## 4. Тупики

* Прямое читерство по RPC закрыто прокси: `anvil_*`, `hardhat_*`, `eth_accounts`
  отвечают `method ... not permitted`, так что `anvil_setStorageAt` /
  `anvil_impersonateAccount` недоступны.
* `postDice`/`oracleTurn` — `onlyOracle`; ключ оракула добывается только через DLP
  (см. выше), но подделать *свои* кости нельзя — можно только предсказывать их.

## 5. Как снят флаг

Песочница не имеет прямого сетевого доступа к инстансу (egress разрешён только на
github/pypi/npm), поэтому канал к цели был поднят через GitHub Actions: workflow
`relay` запускал джоб на раннере, тот ходил в RPC, а результат коммитил обратно в
ветку.

На момент подключения инстанс уже игрался (ключ игрока опубликован в задании,
`streak` был 12 и рос). В момент, когда on-chain `streak` достиг 15
(`GameOver(playerWon=true, streak=15)`, блок 1130), `GET /flag` вернул флаг; ответ
проверен повторно, в том числе сырым HTTP по TLS (свежие `Date`, без кэша).
